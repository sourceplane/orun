# Changelog

orun follows [semantic versioning](https://semver.org). Every release is
published on the [GitHub releases page](https://github.com/sourceplane/orun/releases)
with binaries, checksums, and the list of merged pull requests.

Narrative release notes, which explain what changed and why, live on the
documentation site under
[Release notes](https://orun-docs.pages.dev/release-notes/v2.58.0). The most
recent are:

| Version | Date | Highlights |
|---|---|---|
| [v2.90.0](https://orun-docs.pages.dev/release-notes/v2.90.0) | 2026-10-31 | A build can stop after its scaffold stage and run its live stage later (orun-cloud saas-orun-work WA5): `--driver bootstrap` maps `ORUN_BASELINE_UNTIL` to `--until` and `ORUN_BASELINE_PHASE` to `--phase` beside `--run-hooks --resume` (both set is refused before launch; neither is today's argv), and `--resume` now narrows a `--until` or `--phase` window instead of being refused beside it; a build input declared `lateBound: true` keeps its `default` placeholder only in a run `--until` stops before the last phase, any other run without a value is refused before anything is placed, and a resumed run takes a given late-bound value over the recorded placeholder with no conflict; `orun baseline new --local --until` skips the integrations readiness gate, which reports a full build's needs, and says what is not connected |
| [v2.89.0](https://orun-docs.pages.dev/release-notes/v2.89.0) | 2026-10-26 | A domain, system, environment or other entity whose name gives it a component's catalog ref (`spec.domain: web` on the `web` component) no longer hides the component in Orunbase: the Component keeps the ref and the other entity is left out of the catalog; `orun plan` and `orun catalog refresh` warn, naming both declarations and what to rename; `orun catalog validate` reports it as an error (`catalog.entity.ref.collision`); the catalog snapshot records it as a warning issue |
| [v2.88.1](https://orun-docs.pages.dev/release-notes/v2.88.1) | 2026-10-26 | A job that reads one secret key from two environments gets each environment's own value: the resolve's per-environment answer (`secretsByEnv`) is read under the environment each reference names, never the flat key-only map, so the turso web deploy no longer binds stage to prod's D1 database and prod to stage's; a backend without `secretsByEnv` fails such a job before its first step instead of injecting one environment's value under both names |

| [v2.87.0](https://orun-docs.pages.dev/release-notes/v2.87.0) | 2026-10-24 | A build's bookkeeping asks Orunbase fewer times: `orun.task/ensure@v1` and `orun.integrations/reconcile@v1` remember the epic, its tasks, the connections and the secrets for the run (five minutes), so a bootstrap's task registration takes 9 round trips instead of 15 with no blueprint change; `reconcile` takes `secrets: [{key, template}]`, reading once and creating the missing keys side by side; `orun.pr/land@v1` reads checks every 5 s for a wait's first three minutes, then every 15 s |

| [v2.86.2](https://orun-docs.pages.dev/release-notes/v2.86.2) | 2026-10-24 | A remote run asks GitHub Actions for its OIDC token up to four times, 1 s, 2 s and 4 s apart, when the request gets no answer or a 429/5xx, so a slow token endpoint on a spot runner no longer fails the lane before it claims a job; any other failure is reported at once (orun-cloud saas-live-runs LR13) |
| [v2.86.1](https://orun-docs.pages.dev/release-notes/v2.86.1) | 2026-10-24 | `orun.integrations/reconcile@v1` mints from the connection the build is bound to when a hook pins none (`ORUN_CONNECTIONS`, set by `orun baseline new --from` and by the Orunbase build box), so a product deploys into the account whose workers.dev subdomain its files name; a bound connection that is not active waits instead of falling back to another account |
| [v2.86.0](https://orun-docs.pages.dev/release-notes/v2.86.0) | 2026-10-23 | A build says what it has made as it makes it: `fact` events for the repository, the epic, each pull request (opening → checks → merged, reported while its CI runs) and each probed address with its environment, sent only on change; a done line for every step that matters when its hook authored none; preInstantiate and postInstantiate hooks reported under `phase: ""`; a run-level `started` and `done`/`failed` (none when parked), so Orunbase gives a local build's repository back; hook `label`, `pin` and `quiet`, and probe `targets`; the stream delivered in seq order, a failed landing's URL as `prUrl`, a wait naming its hook, line numbers for mapping-form hooks (orun-cloud saas-build-panel BV3) |

| [v2.84.0](https://orun-docs.pages.dev/release-notes/v2.84.0) | 2026-10-17 | A trigger binding takes its plan from the event: `scope: selected` with `components` and `environments` paths (exact, never empty, `--changed` ignored), `autopush: false`, and `requireRule`, which plans only lanes that opt in with a profile rule naming the binding; the catalog records each opted-in lane as `spec.environments.<env>.manual` (orun-manual-triggers; orun-cloud saas-manual-runs) |
| [v2.83.0](https://orun-docs.pages.dev/release-notes/v2.83.0) | 2026-10-17 | A remote run's steps reach Orunbase as they start and while they run: the `start` event at step begin, the step's output every 2 s or 64 KiB (masked, never split across a secret; the GitHub Actions engine applies workflow commands live), the rest with the `end` event even for a silent step; a job drains its log before `:complete`; a failed log upload retries on a timer (orun-cloud saas-live-runs LR8) |
