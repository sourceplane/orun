Released 2026-09-29. The second CLI half of the Orunbase work-as-code epic
(orun-cloud `saas-work-gitops`): an epic is a directory with a declaration,
and the declaration is checked before it merges.

Binaries and the merged-pull-request list are on the
[GitHub releases page](https://github.com/sourceplane/orun/releases).

## `epic.yaml`

One file per epic under `work.epics`: the slug, the key prefix the epic
reserves, title, state, and the milestones in order with the task keys
under each. Keys are chosen in git and adopted by the platform (the next
release's `orun work sync`); the contract for each listed key lives beside
it under `work.tasks`. See [`orun work`](../cli/orun-work.md).

## `orun work check`

Reads the tree and names every problem in one pass — a malformed
declaration, a listed key with no contract, a contract in a reserved prefix
that no milestone lists, a prefix reserved twice. With `--base` it also
resolves whether the current branch closes its milestone and touches the
epic's status file.

## `orun pr check --standards` gains `work-manifest`

When the repository declares a `work:` section, every tree problem is a
finding (error under `enforce`, warning under `warn`), and the `epic-status`
rule finally has its facts. The shared conformance fixture gains the cases;
the cloud evaluator replays them in lockstep.
