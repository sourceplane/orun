# orun-runner-efficiency — implementation status

| Milestone | Status | What shipped |
|---|---|---|
| **RE0** | ✅ #741 | The analysis, the fleet model (`model.py`) and the expected effect; the scheduler probes committed as regression tests with RE1 |
| **RE1** | ✅ #743 | A whole plan at concurrency > 1 runs on the lane scheduler (`runScheduled`, one scheduler for `--lane` and the plan): each job starts when its upstreams finish; `--component-concurrency` defaults to 0 and is a gate in front of the slot gate when set; `--job` with incomplete upstreams is refused at any concurrency; regression tests in `internal/runner/schedule_test.go` |
| **RE2** | ✅ #744 | `plan.lanes[]` carries `level` (depth in the lane graph, not the jobs' lowest level: what a levelled workflow needs), `upstreamLanes` and `upstreamJobs`; `lane-matrix` entries carry `level` and `upstreamLanes` (a lane-less plan: the job's depth and dependencies); `--github-output` adds `lane-matrix-<k>` per level, `lane-matrix-levels` and `lane-level-count`; `--view lanes` shows level and upstreams; the level-by-level recipe in `concepts/lanes.md`. `estimatedSeconds` and `vcpu` wait for their sources (RE5, RE3) |
| **RE3** | ✅ #745 | `execution.lanes.concurrency: auto` (lanes and groups; `model.LaneConcurrency`): the plan carries 0 and `orun run --lane` resolves it to `runtime.NumCPU()` on the runner, `--concurrency` overriding; `orun plan --max-lanes` / `ORUN_MAX_LANES` override the intent's budget for one plan, recorded in `plan.metadata.lanes` (`mode`, `maxLanes`, `maxLanesFrom`) and named on the summary line. Deliberately opt-in rather than the default: the default stays 4 until RE5's declared `cpu` tells auto what a job needs (the lanes docs measured concurrency 4 on 2 vCPUs at 1.8× slower per job, and deploy jobs are mostly network-bound) |
| **RE4** | ✅ #746 | `.git` is never staged; a staged job's env gets `GIT_DIR`/`GIT_WORK_TREE` (the source repository) and `TURBO_CACHE_DIR` (one cache per run); `--isolation component` copies only `job.path` and links every other top-level entry; composition steps with `scope: lane` (run steps, leading) run once per process for every job whose step is identical after templating — the first job runs it in the shared tree, the rest wait and reuse it (`shared with <job>`) — and a job's private tree is staged after them with dependencies kept (top-level `node_modules` linked, nested ones copied). Not in this milestone: sharing `use:` setup actions (their exported env is per job); `component` as the `auto` default (unsafe while compositions run their own install per job) |
| **RE5** | ✅ #747 | `resources: {cpu, memory, estimatedSeconds}` on job templates, carried to `plan.jobs[].resources`; `jobs[].estimatedSeconds` is the effective weight (declared, or from `orun plan --weights history` — the median of each job's successful runs over the last ten sealed executions — or `--weights <file>`, the committed form `--write-weights` produces); auto mode shares the budget by weight, cuts chains by weight, orders slices by critical path and fills the lightest lane; lanes carry `estimatedSeconds` and `vcpu` (plan and matrix); `concurrency: auto` divides cores by the lane's `vcpu`; `metadata.lanes.weightsFrom`. Unweighted plans are byte-identical |
| **RE6** | ✅ #749 | `orun run` drains on `SIGTERM`/`SIGINT`: the runner's root context is cancelled, running steps are killed with their whole process group (`internal/procgroup`: `Setpgid`, a group kill on cancel, a bounded pipe wait — killing the shell alone left a `sleep` holding the step open for its full length), no further job is admitted (sequential and scheduled paths), each cut job's error is prefixed `interrupted:` and reported failed to the platform, the run exits 143/130 (a second signal exits at once); `--retry` re-opens the cut jobs. The server's `leaseSeconds` from claim and heartbeat is remembered per run and a `running` upstream with no heartbeat for two leases is taken to have lost its runner, in the `--job` claim loop (was a 5-minute constant) and now in a lane's upstream wait too. **Resume at step was deliberately not done**: a job's earlier steps build into a staged tree that no longer exists on the runner that picks the job up, so resuming at a later step would run a deploy without its build; `--retry` re-runs the job from its first step |
| **RE7** | ✅ #750 | The `--job` claim loop and a lane's upstream wait are woken by the run's next event on a backend that long-polls its event stream (`runEventWaiter`, the native coordination backend), re-reading state only then or every 15 s; polling with backoff stays the fallback. `execution.defaults.timeout` (carried as `plan.execution.timeout`) bounds every step whose job and step set none, and the runner's default is 60m (`model.DefaultStepTimeout`); `execution.lanes.upstreamWait` (carried in `metadata.lanes.upstreamWait`) bounds the lane wait, default 60m. Both durations are validated at load |

All eight milestones are on `main` (v2.78.0 release notes, `website/docs/release-notes/v2.78.0.md`).

## Verified on `main` after RE7 (f091ead)

- `go build ./...`, `go vet ./...`, `make verify-generated`: clean. `gofmt -l` lists the same pre-existing files as before RE1 (none added).
- `go test ./...`: 108 packages pass; the one failure, `internal/actions TestRepoEnsureWiresOriginOnlyWhereItShould`, is the pre-existing test that reads a GitHub token from the environment and fails wherever one is set.
- `examples/saas-baseline` product (`orun new`, 2 components × 2 environments): the whole plan runs 4 jobs at 4× in 0.7 s on the scheduler; with `execution.lanes.mode: auto` and `--max-lanes 2` the plan packs `staging/auto-1` (level 0) and `production/auto-1` (level 1, after staging), and `orun run --lane` runs each green in the same execution; `--weights history --write-weights` writes the measured weights.

## Not done, and why

- **Resume at step** (RE6): see the RE6 row. `--retry` re-runs a cut job from its first step.
- **Sharing `use:` setup actions across a lane** (RE4): their exported env is per job.
- **`component` isolation as the `auto` default** (RE4): unsafe while compositions run their own install per job.
- **`--github-output` without `--artifact github`**: pre-existing; the lane outputs are written only when the GitHub artifact is selected and `GITHUB_ACTIONS` is set. Tracked as a follow-up outside this spec.
