## `orun work sync` reserves the declared prefix

A managed epic's pointer records the task-key prefix its `epic.yaml`
reserves (`metadata.key`), and the platform refuses a key in that prefix
from anyone but the sync. Until now the prefix was recorded only when the
sync itself created a task, so an epic adopted with its tasks already
minted stayed unreserved.

`work sync` now sends `keyPrefix` on the epic create, on every update, and
on the stamp, whenever the pointer does not already carry it; the plan
prints it as `keyPrefix <KEY>` among the epic's changes. Pairs with
orun-cloud WG-21, which stamps it and answers 409 `reserved` for a prefix
another epic holds.
