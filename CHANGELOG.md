# Changelog

orun follows [semantic versioning](https://semver.org). Every release is
published on the [GitHub releases page](https://github.com/sourceplane/orun/releases)
with binaries, checksums, and the list of merged pull requests.

Narrative release notes, which explain what changed and why, live on the
documentation site under
[Release notes](https://orun-docs.pages.dev/release-notes/v2.58.0). The most
recent are:

| Version | Date | Highlights |
|---|---|---|
| [v2.79.0](https://orun-docs.pages.dev/release-notes/v2.79.0) | 2026-10-14 | A waiting job keeps the run's state and folds each wake's events onto it: one request per wake instead of the whole event log, the plan object and the frontier, and the first read is the platform's own fold in one request (`GET …/runs/{id}/state`); the runner's waits are woken by progress, not by every heartbeat in the run (`wake=progress`); a step no longer waits for its log upload (a worker per job uploads beside the run, honouring `Retry-After`); `logs --follow` holds each read on the server instead of polling; `catalog push` skips a head it last advanced to the same snapshot (`--force`), `work sync` lists an epic's tasks and docs once and sends only changed docs, and a lockfile-pinned OCI composition source is taken at its locked digest without resolving the tag; `status --watch`, `logs` and `tui` read through the same view; the plan object is uploaded once per run (its digest no longer changes with the clock); the coordination client shares the run's keep-alive transport under a timeout; the session token is reused for 30 s instead of being read from the store on every request; a lane-scoped install may follow the setup actions it needs; a step's relative `working-directory` is applied once by the runner and by the GitHub Actions engine |
| [v2.78.1](https://orun-docs.pages.dev/release-notes/v2.78.1) | 2026-10-14 | A lane's wait for another lane's job backs off again (2, 4, 8, 15 s) instead of re-reading the whole run every 2 s, and a `--job`'s dependency wait no longer sleeps a second interval after a lapsed long-poll (a v2.78.0 regression); `orun status --remote-state --watch` is woken by the run's events instead of polling twice a second (`logs` and `tui` share the coordination backend; `ORUN_COORDINATION=legacy` keeps the old one); `orun plan --github-output` writes `matrix`, `lane-matrix`, the per-level matrices, `plan_id` and `exec_id` whenever `$GITHUB_OUTPUT` is set, with or without `--artifact github` (a workflow that keeps its plan on the platform got no outputs); it warns when `$GITHUB_OUTPUT` is not set |
| [v2.78.0](https://orun-docs.pages.dev/release-notes/v2.78.0) | 2026-10-14 | `orun run --concurrency N` on a whole plan runs on the lane scheduler: a job starts when its upstreams finish, not when the batch it was launched with does; `--component-concurrency` defaults to no cap (it serialised components); every lane carries `level`, `upstreamLanes` and `upstreamJobs`, and `--github-output` writes `lane-matrix-<k>` per level so a workflow can run lanes level by level; `execution.lanes.concurrency: auto` sizes a lane to its runner's cores and `orun plan --max-lanes` / `ORUN_MAX_LANES` size the lane budget to the pool, recorded in `metadata.lanes`; a composition step with `scope: lane` runs once per lane for every job that shares it, `.git` is never staged (`GIT_DIR`/`GIT_WORK_TREE` point at the source), every staged job shares one `TURBO_CACHE_DIR` per run, and `--isolation component` stages only the job's directory; job templates declare `resources` and `orun plan --weights history\|<file>` / `--write-weights` give auto mode per-job weights, so lanes are packed by work and carry `estimatedSeconds` and `vcpu`; `orun run` drains on `SIGTERM`/`SIGINT` (steps stopped, cut jobs reported failed as interrupted, exit 143/130, `--retry` re-opens them) and a waiting job counts a `running` upstream with no heartbeat for two of the server's leases as having lost its runner; remote waits are woken by the run's events on Orunbase; every step is bounded (`execution.defaults.timeout`, default 60m) and a lane's upstream wait by `execution.lanes.upstreamWait` |
| [v2.77.2](https://orun-docs.pages.dev/release-notes/v2.77.2) | 2026-10-14 | Lanes: when more jobs are ready than a lane has slots, the job others wait on goes first — the longest chain of dependents in the plan, across lanes — instead of whichever reached the slot first; a failed job stops only the jobs that depend on it (the plan's `failFast` no longer cancels the rest of the lane), so other lanes stop waiting for jobs nobody will run; each job in flight gets its own Terraform plugin cache; how to size `concurrency` and `maxLanes` |
| [v2.77.1](https://orun-docs.pages.dev/release-notes/v2.77.1) | 2026-10-14 | Lanes running several jobs on one runner: a re-run job's success is seen under `--retry`, a completed job is no longer reported as taken over, tool installers (`setup-*` actions) no longer race on the shared tool cache, and a failed job's held log is printed |
| [v2.77.0](https://orun-docs.pages.dev/release-notes/v2.77.0) | 2026-10-13 | `environments.<name>.url`, `links` and `description` in intent.yaml; every declared environment is a catalog `Environment` entity with its front door as the primary link and `spec.order`; the `Repo` entity is emitted from `metadata.description` alone, with a root `README.md` as the default overview; `links[].role` on the entity envelope |
| [v2.76.0](https://orun-docs.pages.dev/release-notes/v2.76.0) | 2026-10-13 | Lanes: `execution.lanes` groups jobs into the units a runner takes (`job`, `component`, `env`, `auto` without weights), `orun run --lane`, `lane-matrix`, one check run per job; plans without lanes are unchanged |
| [v2.75.0](https://orun-docs.pages.dev/release-notes/v2.75.0) | 2026-10-05 | `orun run <id>` now runs the plan `orun plan` printed; `orun plan` shows each environment's jobs and what they wait on; `orun new` ends in a short summary; a new README recording |
| [v2.74.0](https://orun-docs.pages.dev/release-notes/v2.74.0) | 2026-10-05 | `orun baseline new --from bst_…` continues a bootstrap the console resolved: the id fills the baseline, repository and inputs, no token in the record, the platform reads which door took it |
| [v2.73.5](https://orun-docs.pages.dev/release-notes/v2.73.5) | 2026-10-05 | Closes the platform discipline as code docs epic: descriptions on every page, stale pins and jargon removed, CLI reference matched to the binary (PD6) |
| [v2.73.4](https://orun-docs.pages.dev/release-notes/v2.73.4) | 2026-10-05 | The Verify, plan, execute pillar: a verify step in the runner's walkthrough, selection versus blast radius in change detection, remote state rewritten for Orunbase, `orun run init` (PD5) |
| [v2.73.3](https://orun-docs.pages.dev/release-notes/v2.73.3) | 2026-10-05 | The Ground agents pillar: how agents learn your standards and what keeps them inside them; `mayAffect` and `orun pr check` described accurately; context pack updated (PD4) |
