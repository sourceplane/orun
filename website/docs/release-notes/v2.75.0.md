## Policies are enforced

Until now `policies` on intent groups and environments, and the `policies`
block on execution profiles, were parsed and carried onto each component
instance but nothing acted on them; the [standards](../concepts/standards.md)
page labelled them *declared only*. They are now a typed, enforced vocabulary:

| Policy | Enforced by |
|---|---|
| `pinnedParameters`: a parameter value a component may not override | `orun validate`, `orun plan` |
| `requireProfile`: the execution profile every component in a group or environment must run | `orun validate`, `orun plan` |
| `requirePinnedTerraformVersion`: `terraformVersion` must be an exact version | `orun validate`, `orun plan` |
| `requireCleanGitTree`: refuse to run from a dirty working tree | `orun run` |
| `requireApproval`: pause each job until `orun approve <jobID> policy.requireApproval` | `orun run` |

- **One structured error.** A violation names the component, the environment,
  the policy, and the layer that declared it, one line per broken rule.
- **The plan stays the audit artifact.** Each plan job carries a `policies`
  block with the effective set and, under `sources`, which group,
  environment, or profile declared each rule.
- **Layers add up.** A rule required by a group, an environment, or a profile
  is required; no layer can relax another's.
- **`orun validate` checks policies.** It now resolves composition sources to
  merge presets and to check profile policies, and falls back to the
  intent-level checks with a warning when a source cannot be resolved.

See [policies](../concepts/intent-model.md#policies).

## Upgrading

- **Unknown policy keys fail.** The vocabulary is closed so a typo cannot
  switch a guardrail off. A free-form key that used to be carried silently
  now fails `orun validate` and `orun plan`; remove it or rename it to one of
  the five above. `"true"` and `"false"` strings are still accepted as
  booleans.
- **Declared approvals now block.** An environment or profile that declared
  `requireApproval: true` now pauses `orun run`. Remove it from lanes that run
  unattended in CI. The `examples/` intent's `staging` environment, which
  verifies every merge to `main` in this repository's CI, no longer requires
  approval; `production` still does.
