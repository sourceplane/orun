## `orun work sync` stamps the pointer on every commit

The platform stamps an epic's `managedBy` pointer on the sync's writes.
A run whose epic already matched its `epic.yaml` made none, so an epic
adopted from the console — or one whose declared fields had been set
before the `work-sync` job existed — stayed unmanaged, and the console
kept editing what git owned.

`work sync` now reads the pointer back (`managedBy` on the epic) and, when
no declared field changed but the pointer does not name this repository at
this commit, sends one empty update under the sync header: the stamp,
nothing else. The plan prints it as `stamp  epic <slug> — managedBy`, it
counts as one write, and the same commit run twice stamps nothing.

Pair it with a platform that accepts the empty sync update as a stamp
(orun-cloud WG-18); an older platform answers it with a validation error,
which the run reports as `stamp epic: …` and stops on.
