Released 2026-09-29. The first CLI half of the Orunbase work-as-code epic
(orun-cloud `saas-work-gitops`): the repository names where its epics and
task contracts live, and the tools honour it.

Binaries and the merged-pull-request list are on the
[GitHub releases page](https://github.com/sourceplane/orun/releases).

## `work:` in intent.yaml

```yaml
work:
  epics: work/epics     # default specs/epics
  tasks: work/tasks     # default tasks
  sync: on-merge        # default off
```

`orun task create`, `attach`, `check` and `show`, and `orun pr check`, look
the contract up under the declared `tasks` directory. A repository with no
section behaves exactly as before. An absolute or escaping directory, or an
unknown `sync` word, refuses the intent file at load rather than silently
reading the wrong tree.

## The `task-contract` finding prints the path it looked for

`work/tasks/WG-3.TaskContract.yaml is missing — write it and …`, so the
refusal is the instruction. The shared conformance fixture gains a case
with `contract.path`; the cloud's `orun/compliance` evaluator replays it in
lockstep.

## `metadata.title` on a task contract

A contract may name the task's display title. `orun work sync` (a later
release) creates a task from the tree with it; today it is parsed and
carried, and nothing refuses it.
