## The exchange is retried too

A remote run in GitHub Actions gets its credentials in two requests:

1. it asks GitHub's Actions endpoint for an OIDC token;
2. it exchanges that token with Orunbase (`POST /v1/auth/oidc/exchange`).

[v2.86.2](./v2.86.2.md) retries the first. The second could time out just the
same, with the same 10 s client timeout, and fail the lane before it claimed
a job:

```
✕ remote state auth (oidc exchange): requesting OIDC exchange: Post "https://api.orunbase.com/v1/auth/oidc/exchange": context deadline exceeded (Client.Timeout exceeded while awaiting headers)
```

From this release the exchange follows the same rule as the token request.
It makes up to four attempts, 1 s, 2 s and 4 s apart, when the request gets
no answer or Orunbase answers 429 or 5xx. A refusal is reported at once, for
example a repository no workspace links. An error after retries says how many
attempts were made.

Found by an audit of orun-cloud's runs on production (saas-live-runs LR13).
